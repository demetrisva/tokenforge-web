Separating public utilities from private infrastructure

14 October 2026 · Project architecture

A JWT decoder does not need a server to read a token. A DNS lookup does need a resolver. A vulnerability scanner has a different purpose and should not be another public tool card.

Local computation first

The JWT, CIDR, password, Base64, hash and cron tools run as static browser code. Keeping those calculations local avoids sending their inputs to a lookup service and lets the public frontend stay small.

A bounded public backend

DNS and HTTPS checks use a separate container reached through an outbound Cloudflare Tunnel. The backend accepts hostnames rather than arbitrary URLs or ports. HTTPS connections use a validated, pinned public IPv4 address, preserve the requested hostname for certificate verification and have short timeouts. Results describe the checks performed, including refusals and challenges.

A private administrative path

Administrative SSH and scanner reports use Tailscale. Container rules block new connections into private and VPN address ranges, with a specific allowance for the tunnel connector to call the public API. This is independent of the scanner wrapper’s input checks.

Recovery is application state, too

A Git repository preserves deployment files, but not a live monitoring database or private reports. The recovery process therefore takes a consistent database copy, encrypts application archives and verifies restoration separately from deployment health checks.

These are choices for a small project, not a claim of high availability or a completed security audit.
